Deadline Triage Agent

A Claude Project that triages three parallel tracks from one manually-kept log.

In Daily Use
Tracks triaged 3
Source of truth 1 log file
Agent edits log Never

Three tracks running at once — the FlyRank ML internship, a hackathon, and job applications — each with their own deadlines and states. The design choice that matters most isn't the agent, it's the boundary around it: I keep a plain status log by hand after every real event, and the agent reads it to triage and synthesize, but is instructed never to edit it. That rule is written directly into the file itself, not just held in my head.

status_log.txt

What's open right now across all three tracks?

An agent that's allowed to edit its own source of truth can quietly drift from reality. Keeping the log human-written means every status in it is something I actually did — the agent's job is triage across three tracks at once, not record-keeping.

About

I'm an AI/ML undergraduate at Dawood University of Engineering & Technology, Karachi — but the short version is: I don't trust a model until it's been tested outside a notebook, by a real person, on a real problem.

KarachiWatts started because someone was fed up with unpredictable power cuts, not because it made a good class project. That's the pattern I want every future build to follow — a real person, a real problem, an honest accuracy number, even when that number isn't perfect yet.

This page isn't about one project. It's proof of a way of working — future entries here may be in a completely different domain, and that's by design.
